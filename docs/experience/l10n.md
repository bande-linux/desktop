# Localisation readiness

The owner has not chosen the first languages. This pass makes adding one a translation job: every user-visible string
lives in a Fluent file, numbers and dates go through ICU, a pseudo-locale shows clipped layouts and hard-coded text, and
the right-to-left work is planned here but not built.

## How to add a language

1. Copy each `crates/*/*/locales/en-US/<package>.ftl` to `locales/<tag>/<package>.ftl` and translate it. Plurals use
   Fluent selectors on CLDR categories (`[one]`, `[few]`, `[many]`, `*[other]`); the categories come from
   `intl_pluralrules`, so a Polish or Arabic file can use all six.
2. Add the file to the crate's `Localizer::new(&[("en-US", ENGLISH), ("<tag>", <TAG>)])` list.
3. Run the workspace test `cargo test -p unbound-l10n --test messages`: every id used in code must have an English text,
   and every English id must still be used.
4. Run the pseudo-locale tests (below) with the new language in mind: they catch the same clipping a long translation
   will.

Nothing else changes: language negotiation (`LANGUAGE`, `LC_ALL`, `LC_MESSAGES`, `LANG`) and the fallback to English for
missing messages already work, and `.desktop` files, polkit actions and AppStream data keep their own gettext-style
translations outside Fluent.

## What the code does now

- **Numbers.** `unbound-l10n` formats every Fluent number with ICU4X `DecimalFormatter` for the bundle's language, so
  `{ $count }` and `{ $value }` get the right decimal separator and grouping (`1.234,6 GB` in German).
  `unbound_l10n::number(value, digits)` passes a number with at most that many fraction digits;
  `Localizer::decimal(value, digits)` formats a bare number such as Activity Monitor's CPU percentages. Identifiers
  that only look like numbers (process IDs, exit codes, pairing codes) are passed as text so they are never grouped.
- **Dates and times.** `unbound-datetime` already wrote the bar clock, Notification Center and the lock screen with
  ICU4X for `LC_TIME`. Files' list dates ("Today, 09:12", "28 Oct, 16:20") and the Info, file chooser and launcher
  preview dates now go through it too (`DateFormats::date_time`, `DateFormats::short_time`), so an American locale
  reads "Oct 28, 4:20 PM" and a German one "28.10.2025, 16:20".
- **Errors people read.** File operations and the trash create their own errors from Fluent messages, and errors from
  the system (permission denied, disk full, read-only disk, name taken, …) are rewritten into Fluent sentences before
  Files shows them. Rust's own `io::Error` text is English and never reaches the user for those kinds.
- **Hard-coded strings moved into Fluent:** the Settings chip line ("Apple silicon (8 cores)" with a plural), the
  Software Update failure, the battery chart's spoken summary, the shortcut key names "Space" and "Mission Control",
  the compositor's "can't start" alert, and the file operation errors.
- **Workspace test.** `crates/libs/l10n/tests/messages.rs` reads every crate that has `locales/en-US`, lexes its Rust
  sources (skipping comments, char literals and raw strings) and checks both directions: every literal passed to
  `tr`/`tr_args` exists in English, and every English id is used, either as a literal, through a `format!` pattern
  such as `"banners-{}"`, or by another message. It replaced 23 per-crate tests that each listed their files by hand
  and missed files nobody added (the status crate checked one of its files).

## Pseudo-locale en-XA

`LANGUAGE=en-XA` with the `pseudo` feature of `unbound-l10n` turns every English text into accented, about 35 % longer
text (`Open files…` becomes `ǾǾƥḗḗƞ ƒīīŀḗḗşş…`), while arguments such as file names stay as they are. The feature is only
enabled from `[dev-dependencies]`, so no shipped binary contains it and no `.ftl` file is generated or installed.

Review tests render key surfaces in en-XA and fail on three things, using the text positions in the scene:

1. text cut by its clip or the window edge,
2. two texts drawn over each other,
3. text that still has plain ASCII words, which is hard-coded English (fixture data such as names is allowed).

| Surface | Test |
| --- | --- |
| All 25 Settings panes | `crates/apps/settings/tests/pseudo.rs` |
| The bar, collapsed and expanded, and the shut down, restart and log out dialogs | `crates/shell/bar/tests/pseudo.rs` |
| The polkit password dialog | `crates/services/polkit/tests/pseudo.rs` |

Each test writes its frames to `target/tmp/pseudo/` for a look by eye.

## Right-to-left readiness

Nothing mirrors today. Text itself is shaped and reordered correctly, because Parley runs the Unicode bidi algorithm and
`TextAlign::Start` follows each paragraph's base direction. Everything around the text is laid out left to right.

What breaks under Arabic or Hebrew:

| Area | What goes wrong |
| --- | --- |
| Toolkit rows | Label left, control right; checkboxes and radio buttons before their label; table columns from the left. All need a mirrored horizontal axis. |
| Direction glyphs | `›` disclosure chevrons in Settings, the file chooser, Files and the expanded bar; `‹ { $pane }` back buttons; `go-previous`/`go-next` toolbar icons; the path separator `›`. They must flip or swap. |
| Keyboard | Left and Right in segmented controls, disclosures, menus (open submenu with Right) and the text editor (visual versus logical movement) must swap meaning. |
| Sliders and progress | Fill from the left; volume, brightness and progress should grow from the right. |
| Sidebars and the bar | The Settings and Files sidebars sit on the left; the bar defaults to the left edge. In right-to-left the sidebar moves right and the bar's default edge becomes the right. |
| Window chrome | Window buttons sit on the left of the title bar; they move to the right, and the title stays centred. |
| Menus | Checkmarks on the left and shortcuts on the right swap; submenus open to the left. |
| Fluent | `set_use_isolating(false)` drops the FSI/PDI marks around arguments, so a Latin file name inside an Arabic sentence can pull neighbouring punctuation to the wrong side. |
| Compositor | Window snapping "Left/Right", desktop order in the switcher and the swipe direction between desktops. |
| Terminal | Stays left to right, as terminals do. |

Plan, in order:

1. **Direction source.** Add `Localizer::direction()` (from the negotiated language's script via ICU) and a
   `Direction` in the toolkit `Context`, set once per window. Default left to right.
2. **Isolation.** Turn Fluent isolation on for right-to-left languages, after checking that the renderer draws U+2068
   and U+2069 as nothing.
3. **Toolkit mirroring.** Give rows, stacks, tables, menus, sliders, progress bars and segmented controls a mirrored
   x-axis when the direction is right to left; flip direction glyphs and swap Left/Right keys there. Goldens for an
   en-XB pseudo-locale (en-XA wrapped in right-to-left marks, as Android and Chromium do) cover it.
4. **Shell and apps.** Settings and Files sidebars, the bar's default edge, window chrome and the compositor's
   switcher order follow the toolkit direction.
5. **Text editing.** Visual cursor movement and selection across mixed-direction runs in the editor.
