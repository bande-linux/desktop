# Behaviour decisions

Where a spec is silent, the principles in [`../design/DESIGN.md`](../design/DESIGN.md) decide.
Each decision taken that way is recorded here with its reason, so that it is not reopened by
accident. How each is built is in the subject documents ([compositor](compositor.md),
[toolkit](toolkit.md), [apps](apps.md), [session](session.md)).

## Clipboard and selection

- **Background clipboard access**: reading the clipboard without a user paste is a privilege; copy and paste by the user always work. `wl_data_device` and primary selection stay as they are, since both need keyboard focus. `ext-data-control-v1`, the background read path, is offered only to the clipboard daemon the compositor starts on a socket pair, never to a connection from the listening socket, so no process can obtain it by exec'ing the daemon ([compositor](compositor.md#who-may-do-what)).
- **Clipboard persistence**: the clipboard keeps its contents after the copying app quits; `bande-clipboard` takes over every offered type.
- **Primary selection**: Linux users expect it and it never gets in the way of the clipboard, so it is offered everywhere without a setting. Selected text becomes the primary selection, except in password fields; a middle click pastes it into an editable field or the Terminal and does nothing elsewhere.

## Focus, menus and popups

- **Keyboard focus**: closing or hiding the focused window focuses the app's frontmost remaining window; with none left, the app stays active without a focused window, so its menus and `Ctrl+Q` still apply. An app that is not focused cannot take focus by opening a window. A click focuses and raises. A click on the desktop makes Files the active app, since the desktop belongs to Files: its keys select icons and the rest (`Ctrl+N`, `Ctrl+Q`) reach Files.
- **Menus never outlive a focus change**: every focus change the compositor makes, whatever its cause, closes an open menu first, and a menu whose app dies, hangs or destroys it never keeps the pointer or keyboard. A click beside a menu closes it and is consumed. Otherwise a menu could hold input for an app the user has left.
- **Context menus of Files and the desktop belong to Bande**: no app can add entries to every file's menu; there are no extensions, scripts folders or use of desktop-entry actions. The menus hold what can be done to the object; Open With and New Document (the person's Templates) are the only data-driven lists. An app's own actions appear only on its own surfaces. `ci/release/lint.sh` enforces it. This limits the mechanisms offered; it is not a sandbox.
- **Popup placement**: every menu and popup stays whole on its display and never covers the bar unless it belongs to it or to a full-screen window: menus flip, then slide, and a menu taller than the room scrolls with arrow bands, so every item stays reachable ([compositor](compositor.md#popups)).
- **Escape cancels drags, moves and resizes** (DESIGN §2): a drag and drop ends as a refused drop, and a window move or resize goes back where and as it was, tile or maximize included. A mistaken drag into a snap zone is otherwise only undone by hand. The app gets neither the press nor the release.
- **Drag threshold**: every press that can become a drag waits for 4 px (`past_drag_slop`), the same in every app and shell surface.

## Drag and drop

- **Between apps**: the target proposes the action; Ctrl copies and Shift moves, read live, and the pointer shows the outcome. Selected text drags; within one field it moves, into another it copies unless Shift is held. A target that accepts only copies is never turned into a move, so a file dropped on the Terminal stays in Files. An unconfirmed drop ends without action after 2 s, and an app that dies mid-drag leaves no grab behind, so nothing is deleted and the next click works.
- **Files as text**: copied or dragged files are offered as `text/uri-list` and, for a text field, as their local paths, so pasting or dropping a file into a document or a field inserts its path, never a `file://` address. Pasting files is the keyboard equivalent of dropping them: Mail attaches them and the Terminal types their shell-quoted paths. Files dropped on Mail's main window start a new message with them attached. A folder, a file over 25 MiB or one that can't be read is not attached, and the message says so.
- **Scrolling while dragging**: a drag held near the top or bottom of a Files list scrolls it, faster nearer the edge, so any folder in it can be reached.
- **On the desktop**: a file dropped on empty desktop or a folder there moves when it comes from the same volume and copies from another one (a USB stick or a server), as in Files; Ctrl and Shift choose otherwise. Dragging the desktop's own icons, volumes included, to another spot rearranges them, and a link moves as a link wherever it points.

## Shortcuts

- **Window and app shortcuts**: Super is only for the system and apps keep Ctrl ([decision 0005](../decisions/0005-ctrl-for-app-shortcuts.md)). `SHORTCUTS` in [`shortcuts.rs`](../../crates/libs/keyboard/src/shortcuts.rs) is the one list the compositor matches and Settings and the menus show, so they cannot disagree; only hardware keys are matched outside it. Unbound Super chords reach the app, unless an app bound the chord through the GlobalShortcuts portal (Super or Ctrl+Alt chords only, each one the user allowed, never one another app has), which then gets it from anywhere. `Ctrl+Alt+F1`…`F12` work while locked and inhibited, for a console login; so do the zoom and screen reader keys. `F11` is each app's own full-screen key. `Super+D` shows the desktop; `Super+N` and `Super+S` toggle Notifications and Quick Settings.
- **Force Quit** (`Ctrl+Alt+Esc`, the system menu, a Taskbar icon's menu, Search): a window of the compositor itself, so it opens whatever else hangs and starts no process. It marks apps not answering for 2 s, asks once, and kills through a pidfd (and the app's cgroup scope when it has one), so a reused pid is never hit. The shell is listed as "Taskbar & Desktop" with Relaunch, and Log Out… ends the session even when the shell can't; a shell silent for 2 s gives up the keyboard, and the taskbar and desktop process silent for 5 s is relaunched by itself. Quick Settings waits for Bluetooth, Wi-Fi and its switches on a worker thread, so a slow connection never looks like a hang.
- **App switcher**: `Alt+Tab` switches to the most recent other app on release, so a quick press never flashes the card; held 150 ms, the card shows. `Down` lists the app's windows. Switching activates the app but opens and restores nothing: an app with only minimized windows becomes active without a window, like a Taskbar click. Apps that cannot run windowless get their latest window back.

## Windows

- **Window memory**: a window opens where the last window of its kind closed, per app, window tag and set of displays, clamped onto the display; dialogs and further windows of an open kind cascade instead. A tiled or maximized window is remembered by the frame it returns to. Apps tag their window kinds, so Mail's compose window keeps its own frame.
- **Resume**: apps come back with their windows after a log out, restart or crash. The compositor keeps placement and stacking through `xdg_session_manager_v1`, `bande-app` the app's half ([apps](apps.md)). "Reopen windows when logging back in" is on by default; after an unclean end the next login asks first.
- **Windows resized by their app** keep their top-left corner and spring to the new frame, so Calculator can switch modes in one window. A maximized, tiled or full-screen window that becomes fixed-size floats again.
- **Fill the other half**: tiling a window to a half offers the display's other windows for the free half, unless a window already fills it. Escape, a click elsewhere or any Super shortcut dismiss it.
- **Fixed-size windows cannot maximize, tile or go full screen**: the maximize control is shown disabled and every path to those states is refused, since the window cannot fill them. Moving to another display still works.
- **Tiling menu on the maximize control**: resting 800 ms (or holding 500 ms) on the maximize control offers Left, Right, the quarters, Maximize, Move to Next Display and Restore Size. Opened by resting it is only an offer that takes neither pointer nor keyboard, so a click still maximizes at once; opened by holding it is an ordinary menu.
- **Menu button**: an app's menus open from a ⋮ button beside the window controls, in toolkit title bars and in the compositor's title bar of other apps that export menus (`org_kde_kwin_appmenu`, dbusmenu or GTK's exported menu bar). The App menu is one cascading menu with a "Type to search" field, the app row and each exported menu. There is no separate global menu bar, and windows that draw their own title bar keep their own menus.
- **Window menu**: right-click on a title bar, `Alt+Space`, or an app's own `show_window_menu` (with the serial of a button press it holds or of the last key press it got) opens it for every window, with the keyboard on its first item when opened by keyboard.
- **Keep on Top** (window menu, for every window): the window stays in front of the others on its workspace, below the shell, until it closes. A toolkit window's own menu shows the same state (`bande_app_v1.kept_on_top`).
- **Dialogs and their parent window**: Bande honours `xdg_toplevel.set_parent` for every window. A dialog opens centred on its parent, stays directly above it, follows it, and is minimized and moved with it. A modal dialog (`xdg_dialog_v1`) keeps the keyboard, and a click on its parent shakes it once instead of reaching the parent.
- **Tabs in the header**: any part of a title bar that is not a control moves the window. A drag from a tab decides once: mostly horizontal reorders, mostly vertical moves the window. Apps that tear tabs off (Terminal, Files) keep every tab drag and attach the torn tab to a new window through `xdg_toplevel_drag_v1`, so other windows can take it and Escape puts it back ([compositor](compositor.md#tab-tear-off)).
- **Tabs in Files** show once a window has two; they reorder and tear off as above, and a file dragged over a tab opens it after the spring delay.

## Input

- **Input sources**: the layout is one choice for the session, not per window. Up to four xkb layouts (one keymap's groups), or the system layouts while none are set, so a fresh install types as the system was set up; the login window always uses the system layouts. The `XKBOPTIONS` from `/etc/default/keyboard` apply everywhere, with the person's layouts too, and Settings ▸ Keyboard shows what they make Caps Lock and the Compose key do. Choosing a Caps Lock behaviour or a Compose key there (None, Right Alt, Right Control or Menu) replaces the system's options for that key; Right Alt is offered only while the layouts with the system's options don't use it as AltGr, so a choice never takes away the characters on AltGr (kept from before, it reads "Right Alt (replaces AltGr)"). While the system sets a compose key, "Set by the system" shows that and returns to it after another choice, and when the system sets a layout switch (`grp:`), "Also switch with the keys set when installing" turns it off. `Super+Space` and `Shift+Super+Space` switch to the next and previous source, as do the Taskbar's Input menu, Settings, the login window's and lock screen's input-source button and an xkb switching option such as `grp:alt_shift_toggle`; the new source's name shows briefly. Input methods are not offered.
- **Touch and pen**: a tap or drag works where the mouse would, title bars and window edges included; apps that understand touch or a pen tablet get it directly. A swipe up from the bottom edge of the screen shows all windows (not while the screen is locked).
- **Keyboard and pointer settings**: Settings ▸ Keyboard orders and adds layouts by search, sets key repeat and Caps Lock, lists the shortcuts and keeps Text Replacements. Mouse and Trackpad panes appear only while such a device is connected. Natural scrolling is off for a mouse and on for a trackpad, and tap to click is on, as people expect of each. Every change applies to all devices at once, with only the options a device supports. libinput has no scroll speed, so there is none.
- **Accessibility**: Settings ▸ Accessibility gathers Vision (screen reader, zoom, contrast, transparency, motion, pointer size), Hearing (flash on alert) and Motor (Sticky, Slow and Bounce keys), served live to toolkit, libadwaita and Qt apps through the portal. Bande ships no screen reader; the screen reader switch and `Alt+Super+S` appear only when Orca is installed, otherwise the chord reaches the app. The compositor serves `org.freedesktop.a11y.KeyboardMonitor` so Orca hears every key and its commands never reach the app. Zoom magnifies the whole display, sharp at any level, and follows focus. Pressing Shift five times offers Sticky Keys. Every toolkit window publishes its AccessKit tree on AT-SPI, and so does the compositor's own UI: the switcher, Force Quit, window menus, the overview, the free-half panel, the title-bar buttons it draws and its alerts when the taskbar keeps stopping or a part of the desktop can't start, which take the screen reader's attention as they appear.
- **Keys that wake the display**: the key press that lights a dark display is not typed, so waking cannot type into a password field or a document. Keys pass again once a frame is presented, or at once when the wake fails. Keys pressed while a slow monitor syncs can still arrive, so password fields edit as text fields do (select all, delete, paste), and a stray key is easy to remove.

## Settings and accounts

- **Users & Groups**: Settings manages accounts through AccountsService and polkit (an administrator's password once for a few minutes); your own picture, name and password need none. A logged-in user cannot be deleted, since Debian's `deluser` would remove the home folder before refusing. Without AccountsService the pane is read-only except for your own password. Bande has no automatic login.
- **Passwords**: Settings ▸ Passwords shows nothing until the keyring password is given once, and locks again when you leave the pane, press Lock or the screen locks; the keyring itself stays unlocked. Copied secrets are marked so clipboard history skips them.
- **Sign-in pages**: Bande brings no connectivity check, so NetworkManager contacts no server for one unless the person turns on Settings ▸ Privacy & Security ▸ "Detect sign-in pages on networks" (where another package already installed a check, the switch shows it on). Turning it on installs Debian's `network-manager-config-connectivity-debian` through PackageKit when NetworkManager has no check address, then sets NetworkManager's `ConnectivityCheckEnabled`; turning it off clears that property, which NetworkManager keeps across restarts. The row names the server from `ConnectivityCheckUri`. With it off, joining an open network from Quick Settings or the bar offers to open its sign-in page (clicking the notice opens it too), and Settings ▸ Wi-Fi shows Sign In… on the open network in use; either opens the check address, or Debian's `http://network-test.debian.org/nm` when none is set, only when clicked, so the network redirects it to its sign-in page. When the sign-in page cannot be opened, a notice says why. A browser or Settings opened from a notice gets the notice's activation token, so its window comes forward. Bande's online state never needs the check.
- **Settings failures**: a failed change is shown under the setting it concerns, or the pane's heading, until you leave or act there again; never a generic line that follows you.
- **Mail accounts in other apps**: Mail's accounts (servers in its store, passwords in the keyring under `org.bande.Mail`) are the one place an IMAP account is set up; Notes reads them and adds to them through the same setup sheet, and Mail's setup offers "Also use this account for Notes" (on by default) when Notes is installed. Which accounts Notes uses is kept beside them, so removing an account in Mail stops Notes using it.
- **App settings**: every app with settings has one "Settings…" item on `Ctrl+,` (Terminal `Shift+Ctrl+,`), from `bande-app`. Changes apply at once with no Apply button, in one small file per app that every window watches ([apps](apps.md#app-settings)). System-wide settings stay in `config.kdl`.

## Files, servers and printing

- **Servers, phones and cameras**: every connection is a real mount, so all apps see ordinary files, and `bande-automount` owns them so they outlive Files. SMB, NFS and WebDAV mount through a root helper under `pkexec` with `nosuid,nodev` forced; SFTP, phones and cameras through FUSE as the user, and devices only in an unlocked session. Nearby computers come from Avahi's D-Bus interface and are browsed only while a Files window shows the Network folder; without `avahi-daemon` the folder says so above its servers and offers to install it. A server that stops answering is marked, then force-unmounted after a minute and remounted when it returns, and no UI thread touches a network mount, so a dead server never hangs Files. Files on a server delete after asking, as servers have no Trash. Settings ▸ Sharing turns on SSH and Samba sharing as administrator (see [Sharing](session.md#sharing)).
- **Printing**: a network printer simply appears once Avahi is installed; no driver is installed and no printer added. `bande-printd` finds driverless IPP printers through Avahi's D-Bus interface and runs only while something prints or watches; Avahi is not installed with Bande, as it announces the computer on the network, so until then Settings ▸ Printers says so and offers to install it, and printers added by address still work. It prints over `ipps` pinned to the certificate first seen for that printer (by its uuid, so a new address keeps the check), since printers' certificates are self-signed, and resolves the printer's `.local` name each time it prints. A job is kept on disk until printed; one whose record cannot be read is reported and its document kept. Closing the app or logging out loses nothing. Printers that do not take PDF get raster drawn in a confined worker. CUPS is optional and installed on demand from Settings ▸ Printers for apps that print through it (the Browser, LibreOffice, GTK and Qt apps) and for USB and older printers; the same install adds Avahi, which `cups` recommends, so those apps see the same network printers, and the row says so when Avahi is missing. One print dialog serves every app, and its preview is what prints ([apps](apps.md#printing)).
- **Listing**: names sort by the collation of the person's language (`LC_COLLATE`), with numbers in names in numeric order, and sizes use its decimal separator (`LC_NUMERIC`). Names a folder's `.hidden` file lists are hidden like dot files. The inspector changes an item's access and owning group, and applies a folder's to everything inside it after asking. Files opened from Files or the file chooser are added to `recently-used.xbel` (the Desktop Bookmark Specification), so every app lists them, unless Settings ▸ Privacy ▸ Recent files is off (`remember-recent-files`); a file another program left cut short is not rewritten, so its other entries are never lost. A disk that is busy when ejected names the programs with something open on it before offering Force Eject.
- **Glance**: `Space` on a selection in Files or the desktop previews it and `Space` or `Escape` closes it. The panel never takes the keyboard, so the arrows keep moving the selection underneath. Images, SVG, PDF, fonts and archives are parsed in a confined child that is time- and memory-limited and cannot gain privileges, and hands back only screen-sized pixels, so a damaged file of these kinds can't take the shell, Files or Search down; the picture reader can only compute and write its answer once it has read the file, and the font reader once it has laid out its sample. Text, code, Markdown, HTML and RTF are read (at most 1 MiB) and highlighted on a background thread of the viewer itself. An SVG is laid out in the picture reader, its text with the system fonts and never with files it links to, before the reader is confined, and drawn after. HEIF/HEIC and AVIF photos are decoded by Debian's libheif, a C library, loaded only in such a picture reader (for Viewer and thumbnails too), which may start threads but nothing else. libheif1 is recommended, not required: without it the preview or Viewer says that it needs that package. A file it cannot draw itself (RAW, office documents) shows what an installed thumbnailer makes of it. When a picture is damaged, unreadable, too large or takes too long, a video can't be played or a PDF can't be opened or is locked, the preview says so, and so does the accessibility description. PDF pages are kept only near the visible ones. While video or audio plays, `K` plays and pauses, `M` mutes and `Ctrl+Left`/`Ctrl+Right` seek, and its controls are in the accessibility tree, as are an image's size and the text of a text, code or Markdown preview. A space typed within a second of type-ahead continues the name instead of opening Glance; an arrow key or a click ends type-ahead. A font's preview has Install (`Ctrl+Shift+I`), which copies it into `$XDG_DATA_HOME/fonts`, where apps opened afterwards find it, under a numbered name when a different font already has its file name. It shows Installed when the font already lies in a font folder or the same file is installed.
- **Thumbnails** (freedesktop Thumbnail Managing Standard, shared with other apps) are made in the same kind of confined, time- and memory-limited child: images, the first page of a PDF (hayro) and fonts (Bande's text renderer) built in, anything else by an installed `.thumbnailer`, run from that child with a minimal environment and its errors logged.

## Shell

- **Shell clients**: the compositor starts `bande-shell` and `bande-screenshot` on socket pairs and restarts them, so a crashed shell comes back without the session noticing. Only they see `bande_shell_v1` and the toplevel list. The shell is one process for every display's desktop and taskbar, the banners, panels and Search, sharing one GPU device and font database. The lock screen is a process of its own, so the shell can never hold the session open.
- **Bande menu** (right click on the logo): About, Settings, Force Quit, Sleep, Restart, Shut Down, Lock Screen, Log Out. Session-ending choices ask first and act by themselves after 60 s; apps that ask about unsaved work come forward, and one that hangs is given up on after ten seconds so the computer still goes down. Open apps are reopened at the next login. After a crash they are not reopened by themselves, since the app that brought the session down would come straight back: "Reopen your apps?" lists them and asks first.
- **Taskbar**: one bar per display with no separate menu bar; Settings offers only its edge, size, floating and auto-hide. It holds the logo (Search), the Taskbar icons, the Trash, workspaces, status items, Quick Settings and the clock, which shows a dot while notifications wait. The focus frame always shows which app `Ctrl+Q` quits, also after its last window closed. Over a full-screen window the bar hides and waits 300 ms before showing, so games and video do not reveal it by accident. Battery percentage is in the battery menu, not the bar.
- **Taskbar icons**: kept apps, then running ones, then the Trash. A click opens the app or brings all its windows forward. The icon menu lists windows, desktop-entry actions, Keep in Taskbar, Open at Login and Quit. Dragging reorders, keeps or removes; files dropped on an icon open in that app or go to the Trash. Unity launcher badges and progress are shown, and an app asking for attention without a valid activation token only pulses, so no app can steal focus.
- **Quick Settings**: a card beside its bar item with the person, Lock and power, tiles for Wi-Fi (its networks behind the tile), Bluetooth (the Taskbar's device menu behind the tile), Airplane mode, Do Not Disturb, Night Light, Dark style (with Automatic it shows the style in effect, and a second tap returns to Automatic), Power Saver and Screen Recording, each shown only while its service answers; a menu opened from a tile by keyboard opens below that tile; then brightness, volume and output, the microphone and Now Playing for MPRIS players. The media keys control the player shown there, also while locked. Volume keys show a level card that never takes input.
- **Notifications**: a notification shows as a banner and stays in Notifications afterwards, grouped by app; critical ones stay on screen and transient ones are never kept. Do Not Disturb is a focus mode, by hand or on a daily schedule: notifications go to the center without banners, critical ones still break through, and missed banners are not replayed. With previews off, only titles show. Resting on a banner holds every banner. Banners slide from and back into the clock's corner.
- **Search**: a tap of Super opens a search card that takes the keyboard, typing live from the first frame; nothing behind it is dimmed, and a click beside it also reaches what it lands on. It finds apps, Settings panes (not Wi-Fi, Bluetooth, Mouse or Trackpad while the computer has none, checked each time it opens), calculations and conversions, folders and documents by name and content, and the mail, events and contacts apps offer, ranked by use. An empty query shows recent apps, recent documents and every app, so there is no separate app grid. Settings ▸ Search turns each kind off and keeps folders out of search, honoured by the index and by Files at once. `Super+V` opens clipboard history and `Super+.` emoji and symbols.
- **Search index**: `bande-indexer` keeps one on-disk index of the home folder for Search and Files, so results are there the moment the shell restarts. Indexing runs at idle priority and never delays a query, pauses when memory is short, and sleeps with nothing changing. Documents are read in a confined child per file, and the index keeps no copy of the text. Hidden folders, caches, excluded folders, other mounts and encrypted folders are never indexed, so an encrypted volume's contents never leave it.
- **Time zone when travelling**: each time the computer comes online, the shell reads the country the Wi-Fi hardware transmits for (nl80211's regulatory domain, which the kernel takes from the access point's country, so nothing is sent; a card's own domain counts only when its firmware manages it from the networks nearby, since other drivers keep the country the card was sold in). When none of that country's zones (`zone.tab`) shows the clock's current time, it asks to change to the country's zone, or, where its zones differ, offers to choose one in Settings ▸ Language & Time, which clicking the notice also opens. Changing goes through `timedated` and polkit; Keep Current remembers the country in `$XDG_STATE_HOME/bande/time-zone-kept` so it is not asked again; dismissing the notice stops the question for that country until the next login.

## Power and display

- **Night Light** warms every display from sunset to sunrise at the time zone's location, or between set times, through each display's gamma ramp, fading over a minute ([compositor](compositor.md#night-light)).
- **Sleep when idle**: by default the computer sleeps when the display turns off; `idle suspend-after` changes or disables it. On battery the display turns off sooner (5 min) and the computer sleeps with it; `display-off-after-on-battery` and `suspend-after-on-battery` set those, and Settings ▸ Lock Screen shows them only when the computer has a battery.
- **Power button**: in a Bande session a press locks and, where the computer can sleep, sleeps; the compositor holds logind's power-key inhibitor for this only while its session is the active one, so the login window, the console and other desktops keep Debian's behaviour, and an administrator's `HandlePowerKey=` in logind's configuration always wins. Holding the button down is left to the firmware's forced power-off, the way out of a hung session ([compositor](compositor.md#sleep-and-wake)).
- **Power settings**: Settings ▸ Power shows only what the computer has (battery history and health, charge limit, lid, power modes), and when something is missing it says what and why rather than showing an empty pane.
- **Sleep and wake**: the lock screen shows the moment the computer wakes, never the desktop. Every way to sleep goes through logind, and sleep waits (at most 3 s) until the lock screen is on every display ([compositor](compositor.md#sleep-and-wake)).

## Sound

- **Event sounds**: few, short interface sounds of Bande's own theme (Datum §10), played by `bande-sound` with the freedesktop names and skipped while muted. Settings ▸ Sound picks the alert, scales every event sound and turns interface sounds and the volume tick off; alerts and notification sounds stay. The volume tick plays when a slider is let go, never during the drag. Settings ▸ Sound also sets each playing app's volume.

## Apps

- **Signed and encrypted mail**: Mail speaks both open standards, OpenPGP and S/MIME, since professional correspondents use either. Keys stay in GnuPG, as Debian users already keep them: `gpg-agent` holds the secret keys of both standards (S/MIME through `gpgsm`, as other Linux mail clients do), so existing `~/.gnupg` keys, smartcards and the agent's passphrase cache work, and Mail never sees a secret key. A Bande-only key store, the Sequoia keystore or NSS would have hidden those keys or split them in two places. Hostile input (messages, signatures, certificates) is parsed by memory-safe Rust (Sequoia on Debian's Nettle backend; RustCrypto `cms`, `rustls-webpki`), not by `gpg`/`gpgsm`. A banner states only what was proven, and only a signature over the whole message counts. Nothing is fetched without a click (WKD on Look Up Key, no keyserver, no Autocrypt), decrypted text stays out of search unless allowed, and Encrypt never falls back to plain text ([Mail](../../crates/apps/mail/README.md)).

- **Daemon start**: `bande-notify` starts on the first notification through D-Bus activation. Services for the whole session are systemd user units wanted by `graphical-session.target`, with activation files that defer to them. `bande-clipboard` is started by the compositor, because its trusted connection has to come from it.
- **Opening apps**: every launch path goes through `bande_xdg::spawn_detached`, which puts the app in its own `app-bande-<id>-<pid>.scope`, as systemd's desktop integration asks, so memory pressure and Force Quit act on the whole app. An app that crashes posts "quit unexpectedly" with Reopen and Show Report; one that fails within 5 s of opening posts "could not be opened". A normal quit or a kill posts nothing.
- **Apps in the background**: an app can run windowless without counting as running (`bande-app`'s `--background`), so Calendar's alerts fire with Calendar closed. It shows no dot, Force Quit and the switcher leave it out and logout does not wait for it.
- **Notes format**: Notes keeps each note as a message in the account's Notes folder (its subfolders are note folders) in the IMAP notes format other clients use: `X-Uniform-Type-Identifier: com.apple.mail-note`, `X-Universally-Unique-Identifier`, `X-Mail-Created-Date`, `Date` as the last change, the first line as `Subject`, and a quoted-printable `text/html` body of `div`, `br`, `b`, `i`, `u`, `strike`, `h1`–`h3`, lists and links. A private format would have kept the notes from every other device; the format keeps them on the person's own server and readable elsewhere. An edit appends the new version and expunges the old one, keeping the identifier and creation date; when the same note changed elsewhere in the meantime, both versions are kept as separate notes rather than losing text. Other HTML is reduced to that subset when read; a note with pictures or attachments is shown read-only until Edit Anyway, since saving it keeps only its text. Pinning is not part of the format, so Notes has none.
- **App identity**: a window is matched to its desktop entry by `bande_xdg::find_app` (exact id, case, `StartupWMClass`, reverse-DNS part, `Exec`), so an app shows one icon and its own name everywhere. Keep in Taskbar for an app with no entry writes one to `~/.local/share/applications`, never overwriting a file.
